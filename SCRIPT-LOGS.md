# Account LOG

`/log` uses the existing Google/Discord login and an independent write-only link per provider/account. Copy the link into the supported script's LOG controls and enable LOG. Break places these controls in Settings / LOG; Anime Dice and Throw Food have a LOG tab. Existing Key/HWID verification remains required by the main script loader.

The script immediately registers its game session, posts newly obtained animals/characters in batches, and sends a 15-second balance/presence heartbeat. The page refreshes every two seconds while visible. A session becomes offline after 45 seconds. Each drop card uses the supported game's own local map picture; it does not request item thumbnails. Level/status/income appear when available. Currencies are stored as decimal/exponent strings, avoiding database integer overflow for game balances. Each of the three scripts has independently saved minimum item income and multiselect rarity filters; both conditions must match before an event is queued. Zero minimum and no selected rarities preserve the default of logging all new drops.

Only authenticated owners read their feed. Link creation/replacement requires same-origin POST. Links use independent random IDs and domain-separated 128-bit HMAC tokens; only token hashes are stored. They cannot read logs or grant website/Key access. Replacing a link rejects the old one. POST bodies are bounded and validate the three supported games, event IDs, item counts, metadata and Roblox image hosts. Immutable event IDs and unique owner/event constraints deduplicate network retries. No arbitrary image URL is fetched. Initial script snapshots establish a baseline and do not replay existing inventory. These are client-observed game logs, not financial receipts.

Retention is at most 1,000 events/account; the page shows the latest 500. Once all of an account's script sessions have been inactive for more than one hour, both its history and sessions are deleted transactionally. A one-minute Cloudflare cron runs this cleanup even when the website is closed. Reads and reconnects also enforce expiry; a reconnect clears expired history before refreshing presence. The page drops previously cached records using the server's current history start. A live session in any of the three maps keeps the account's history; simply viewing the website does not. Personal links are retained. Polling does not write persistent rate-limit rows. Ingest/manage mutations retain rate limits. No new schema migration is required for this update, and Keys, devices and purchase orders are untouched.

Validated with real handlers + SQLite account isolation/rotation/retry/session tests, parser/migration tests, desktop/tablet/mobile browser fixtures, TypeScript, production build and live anonymous authorization probes. Browser tests use mocked account data, and script execution uses Roblox mocks; no live in-game verification is claimed. Production release evidence is in `script-log-release.json`. See the script repository's `tools/website-log/README.md` for source boundaries and runtime publishing.
